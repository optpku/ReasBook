# Design System: ReasBook static reader

## Overview

**Creative North Star: "The Mathematical Reference Handbook"**

ReasBook presents formalized books and papers as a calm, addressable mathematical
reference. Original chapter structure and statement numbering establish the
hierarchy. White paper, a pale navigation rail, and restrained violet links
support sustained reading and movement between the literature and Lean.

This system covers the static reader generated by `ReasBookWeb` and the shared
project catalog. Its source of truth is `ReasBookWeb/static_files/style.css`,
the shell in `ReasBookWeb/ReasBookSite.lean`, the reader markup in
`ReasBookWeb/scripts/gen_sections.py`, and the catalog renderer in
`sdk/common/src/reasbook_sdk_common/catalog.py`. It does not replace the separate
review application's design system or the native documentation generator's
mathematical-content styling. The surface contract owns page strategy;
`PRODUCT.md` owns product commitments.

**Key Characteristics:**

- Serif mathematical reading, sans navigation, and monospace Lean.
- Continuous numbered statements separated by fine rules.
- Compact chapter directories and direct resource links.
- Flat, bounded reading surfaces with visible keyboard and location states.

## Colors

The palette pairs neutral paper and charcoal with a quiet violet ink accent.
The frontmatter preserves the exact source values; names below describe roles.

### Primary

- **Violet ink** (`reader-link`): links, keyboard focus, selected navigation text,
  and the targeted statement's top rule and title.
- **Deep violet ink** (`reader-link-hover`): reader link hover text.
- **Pale violet selection** (`reader-active`): active navigation and reader text
  selection; the catalog uses its navigation neutral for text selection.
- **Pale violet hover** (`reader-hover`): reader navigation, chapter-link, and
  contents-toggle hover fills.

### Neutral

- **White paper** (`reader-surface`): the reading page and catalog.
- **Ink-gray rail** (`reader-navigation`): navigation; also catalog row hover.
- **Charcoal ink** (`reader-ink`): mathematical prose, headings, and navigation.
- **Quiet gray** (`reader-muted`): scope notes, unavailable resources, and
  secondary text.
- **Fine rule** (`reader-rule`): navigation boundary, statements, catalog rows.
- **Code paper** (`reader-code`): the shallow tonal inset behind Lean excerpts.

### Named Rules

**The Location Is Visible Rule.** Active navigation combines a tinted fill,
violet text, heavier weight, underline, and `aria-current`. A statement target
uses a violet rule and underlined title. Location must remain identifiable
without relying on color alone.

## Typography

Reading uses the `reader-serif` stack; navigation and controls use
`reader-sans`; Lean uses `reader-mono`. These are system fallback stacks, with
no bundled or downloaded font. The catalog's supporting UI uses
`system-ui, sans-serif`. A particular installed face is not guaranteed across
operating systems.

The hierarchy is purpose-specific rather than a fixed modular ratio:

| Role | Size / line height | Weight | Application |
| --- | --- | --- | --- |
| Display | 2.5rem / 1.25 | 400 | Book, chapter, paper, and catalog h1; at most 30ch |
| Display, narrow | 2rem / 1.25 | 400 | h1 at widths up to 640px |
| Headline | 1.375rem / 1.25 | 600 | Main h2, including chapter-directory headings |
| Statement title | 1.1875rem / 1.5 | 600 | Numbered mathematical heading |
| Body | 1.125rem / 1.75 | 400 | Mathematical prose, at most 72ch |
| Chapter link | 1.125rem / 1.5 | 400 | Chapter directory with tabular numerals |
| Catalog link | 1.25rem / 1.5 | 400 | Project list entry |
| Navigation base | 0.875rem / 1.45 | 400 | Contents rail |
| Resource label | 0.875rem / 1.75 | 400 | Home/chapter resource links |
| Statement resource | 0.75rem / 1.75 | 400 | Documentation and source beside a statement |
| Scope note | 0.8125rem / 1.6 | 400 | Excerpt coverage or availability clarification |
| Contents toggle | 0.9375rem / 1.5 | 600 | Mobile contents control |
| Lean excerpt | 0.875rem / 1.65 | inherited | Scrollable `pre`; 0.8125rem up to 640px |

Within navigation, work titles use 1rem/1.5 at weight 650; chapter summaries use
0.9375rem at weight 550. File links use 0.8125rem, increasing to 0.875rem at
the mobile-navigation breakpoint. Current links use weight 650. Inline code in
prose uses 0.85em. Main h3 uses 1.1875rem/1.25; the statement-title role above
is its own explicitly styled heading pattern.

**The Three Reading Roles Rule.** Preserve the serif/sans/monospace distinction:
mathematical reading, navigation, and formal source each have a recognizable
voice. Actual typeface selection follows the platform's available fonts.

## Layout

Above 1000px, a fixed 18rem contents rail occupies the left edge. It fills the
viewport height, scrolls independently, and has a 1px right rule. Main content
starts after that rail with `3rem 3rem 5rem` padding. Its inner wrapper is
centered within the remaining space and capped at 54rem. Prose is additionally
capped at 72ch. Main headings wrap long titles and balance their lines.

At widths up to 1000px, navigation becomes a sticky top region. The contents
control is at least 48px tall; expanded contents scroll within half the viewport
height. Main content loses its left margin and uses
`2rem max(1.25rem, env(safe-area-inset-left)) 4rem` padding. Navigation targets
are at least 44px tall. The rail remains visible if enhancement JavaScript is
absent; collapsing is enabled only after the toggle is created.

At widths up to 640px, the page title shrinks, the chapter directory becomes
one column, statement headers stack, and code padding becomes 0.875rem. The
desktop directory uses two equal columns with a 2rem gutter, except that fewer
than five chapters always use one column. Chapter rows are at least 52px tall.

The catalog is centered without a rail: `max-width: 54rem` and
`3rem 1.25rem 4rem` padding; its top padding becomes 2rem up to 640px. That
maximum applies to the catalog's content box. The reader's 54rem maximum
applies to its inner wrapper.

Spacing separates meaningful reading units: 1rem around headings and code,
1.5rem above a statement, 2rem between statements or resource groups, and
2.5rem before h2 headings (2rem on narrow screens). Smaller increments serve
navigation nesting and control padding. Long Lean lines scroll within their
own excerpt instead of expanding the page.

## Elevation & Depth

The reader and catalog have no shadows. Pale surface fills, whitespace, and
1px rules distinguish navigation, code, and consecutive mathematical entries.
Hover fills change over 120ms with `ease-out` only for reader navigation and
chapter links, and only when reduced motion is not requested. Contents and
location changes are immediate. The sidecar records these behaviors and
breakpoints because the token schema does not support them.

## Shapes

The page and statement flow remain unboxed. A single 4px radius softens reader
navigation targets, chapter links, and Lean excerpt backgrounds. Catalog rows
are square and divided by top rules. Keyboard focus is a 2px violet outline
offset by 3px; it is not a shadow or decorative border.

## Components

### Chapter directory

A compact list of existing chapters. Labels retain `Chapter 01` numbering and
tabular numerals. Serif links use charcoal at rest and gain violet text,
underline, and pale hover fill on interaction. The two-column and short-list
rules are described in Layout; home directories do not repeat the item list
or append item counts.

### Contents navigation

A sans-serif hierarchy of work, chapter/section, and file/item links. Native
`details`/`summary` controls expose the hierarchy. Nested lists use a 0.75rem
left inset. Hover adds a pale fill; current entries combine fill, underline,
weight, and `aria-current`. Following a statement fragment opens its ancestor
groups and scrolls the navigation panel only when necessary. It does not move
the mathematical target out of view. Unavailable entries are muted text.

### Resource links

Documentation, Lean source, and book-home links form a wrapping, unboxed row
with a `0.25rem 1.5rem` gap. Home and chapter links have 44px minimum height.
Reader link hover darkens the violet. Unavailable resources use muted
`aria-disabled` text without an active destination. Keep the labels specific
to the actual resource.

### Numbered statement

A continuous reading block, with a 1px top rule, 1.5rem top padding, and 2rem
bottom separation. Its header places the serif mathematical label beside
small sans resource links; these stack at 640px. The title has heading
semantics. The stable statement ID supports direct fragments, including
selected-clause fragments. A targeted title is underlined and violet. Prose
and the associated Lean excerpt follow in reading order, without a card shell.

### Lean excerpt

A monospace `pre` on code paper with 4px corners, 1rem padding, line height
1.65, and horizontal overflow. Narrow screens use the smaller code role and
padding. Shell enhancement makes excerpts keyboard-focusable regions labeled
“Lean statement excerpt” and disables browser translation for the region.
Keep signatures and source context intact; excerpt content is not an invented
proof or a claim of complete documentation.

### Mobile contents toggle

A text button labeled “Show contents” or “Hide contents” in the sticky
navigation area, with a transparent resting background and pale hover fill.
It controls the rail through `aria-controls` and `aria-expanded`. Escape,
ordinary navigation, and fragment changes close the expanded contents;
Escape restores focus to the control. Breakpoint changes reset the mobile
open state. There is no overlay, floating icon, or animated transition.

### Project catalog

An ordered source-provided sequence of project links under a serif title and
short description. Each full-width text row has a 1px top rule and
`1rem 0.5rem` padding. Hover adds the navigation neutral and an underline.
The shared renderer is self-contained and requires no JavaScript. Its footer
provides the project-information link. An empty catalog displays its existing
availability message rather than invented entries.

### Scope note

A small sans paragraph in muted ink, capped at 80ch, with
`-0.75rem 0 2rem` container margins. It explains relevant excerpt coverage or
availability without competing with the mathematical heading. Preserve the
meaning of source and attribution information; preview tooling banners are
not part of this component or the durable visual system.

## Do's and Don'ts

### Do:

- **Do** preserve original numbering, attribution, direct statement anchors,
  and the distinction between prose and formal source.
- **Do** use the measured reading widths and responsive contents behavior.
- **Do** keep keyboard focus visible and current location identifiable by
  more than color; preserve the skip-to-content link.
- **Do** use real source/documentation destinations and truthful availability.
- **Do** treat system font stacks as fallbacks and verify mathematical glyphs
  and Lean monospace rendering on the target platform.

### Don't:

- **Don't** replace continuous mathematical text with promotional cards,
  decorative imagery, or shadow-based hierarchy on this reading surface.
- **Don't** turn the compact book home into a duplicate inventory of statements
  or add chapter counts to its labels.
- **Don't** remove code overflow, stable fragments, or no-JavaScript access to
  contents in pursuit of a cleaner screenshot.
- **Don't** extend these rules into the separate review application or claim
  that this record changes native documentation-generator styling.
- **Don't** promote local-preview banners, fixture text, or release-validation
  claims into the reusable system. No shipping raster assets are used;
  raster provenance is not applicable.
